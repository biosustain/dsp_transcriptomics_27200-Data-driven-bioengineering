Extracting Results

results() extracts the Wald test output for a given contrast. By default DESeq2 applies independent filtering — it removes genes with very low mean counts before multiple testing correction, which increases power to detect DE genes at a given FDR threshold.

We set alpha = 0.05 to optimise filtering for a 5% FDR cutoff.

Code 
res <- results(dds,
               contrast = c("condition", "treatment", "control"),
               alpha    = 0.05)

summary(res)
## 
## out of 16238 with nonzero total read count
## adjusted p-value < 0.05
## LFC > 0 (up)       : 2289, 14%
## LFC < 0 (down)     : 1865, 11%
## outliers [1]       : 0, 0%
## low counts [2]     : 0, 0%
## (mean count < 6)
## [1] see 'cooksCutoff' argument of ?results
## [2] see 'independentFiltering' argument of ?results

We report genes that change by at least 2-fold, so that is what we should test for. The call above asks whether the fold change differs from zero; a gene can clear that bar comfortably and still be nowhere near 2-fold. Filtering the output afterwards on |log2FC| >= 1 does not fix this, because the filter is applied to the estimate, not to the hypothesis: nothing bounds how many genes with a true change below 2-fold slip through on a lucky estimate.

results() can test against the threshold directly. lfcThreshold = 1 moves the null hypothesis from “no change” to “no more than 2-fold”, and altHypothesis = "greaterAbs" asks for changes larger than that in either direction. The adjusted p-values then control the error rate for the claim we actually make.

Code 
res_thr <- results(dds,
                   contrast      = c("condition", "treatment", "control"),
                   lfcThreshold  = 1,
                   altHypothesis = "greaterAbs",
                   alpha         = 0.05)

summary(res_thr)
## 
## out of 16238 with nonzero total read count
## adjusted p-value < 0.05
## LFC > 1.00 (up)    : 145, 0.89%
## LFC < -1.00 (down) : 93, 0.57%
## outliers [1]       : 0, 0%
## low counts [2]     : 0, 0%
## (mean count < 6)
## [1] see 'cooksCutoff' argument of ?results
## [2] see 'independentFiltering' argument of ?results

📘 Note: We keep both results objects. res_thr decides significance. res still provides the Wald statistic used to rank genes for GSEA in script 03 — that ranking must stay on the test against zero, because with a threshold the statistic is pulled to zero for every gene near the boundary and the ranking would be distorted.

Reading the summary. Of 16,238 tested genes, about 2,290 are up and 1,870 are down at padj < 0.05 (roughly 14% and 11%). Two lines are worth noting: outliers = 0 means no gene was flagged by Cook’s distance as driven by a single extreme sample, and low counts = 0 means independent filtering did not need to remove additional low-expression genes (the pre-filtering in script 01 already handled them). A large but balanced set of up- and down-regulated genes is the expected signature of a strong, genome-wide treatment response — dexamethasone is a potent transcriptional regulator, so this magnitude is biologically plausible.

The results table contains one row per gene with the following columns:

Column Description
baseMean Mean normalised count across all samples
log2FoldChange log2(treatment / control)
lfcSE Standard error of the log2FC estimate
stat Wald statistic
pvalue Raw p-value
padj Benjamini–Hochberg adjusted p-value

Log2 Fold Change Shrinkage

What is this step and why do we need it?

After running DESeq2, every gene gets a raw log2 fold change (LFC) estimate. For lowly expressed genes, these estimates are unreliable — a gene with 1 count in control and 3 in treatment looks like a 3-fold change, but this is just noise from low counts.

lfcShrink() corrects this using empirical Bayes shrinkage: it pulls noisy estimates (low counts, high uncertainty) toward zero, while leaving well-supported fold changes (high counts, consistent signal) largely unchanged. Think of it as a confidence-weighted adjustment.

⭐ Important: shrinkage does not change your p-values — those come from the results() call above and are carried over unchanged. It only changes the fold-change estimates. Significance now comes from the test against the 2-fold threshold, so shrinkage no longer decides which genes qualify. It still matters for everything that reads the fold change itself: the volcano, the heatmap and the ranking of the strongest effects.

Why apeglm? Three shrinkage methods exist in DESeq2: - apeglm — most accurate for simple two-group comparisons like ours ✅ - ashr — more flexible; needed when comparing two non-reference groups - normal — the original method, now outdated and not recommended

For a treatment vs control design, apeglm is the right choice. See Zhu et al., 2019 for benchmarks.

Code 
# Pass res = res so the shrunken object inherits the p-values and independent
# filtering from the results() call above (alpha = 0.05) instead of recomputing
# them at apeglm's default alpha.
res_shrunk <- lfcShrink(dds,
                        coef  = "condition_treatment_vs_control",
                        type  = "apeglm",
                        res   = res)

summary(res_shrunk, alpha = 0.05)
##

## adjusted p-value < 0.05
## LFC > 0 (up)       : 2289, 14%
## LFC < 0 (down)     : 1865, 11%
## outliers [1]       : 0, 0%
## low counts [2]     : 0, 0%

Sorting and Filtering Significant Genes

We order genes by adjusted p-value and keep those with padj < 0.05 from the thresholded test. There is no separate fold-change filter: the 2-fold requirement is already part of the hypothesis.

Code 
res_df <- as.data.frame(res_shrunk) %>%
  rownames_to_column("gene") %>%
  mutate(
    stat   = res[gene, "stat"],         # Wald statistic vs zero; lfcShrink() drops it. Ranks genes for GSEA in script 03
    pvalue = res_thr[gene, "pvalue"],   # significance comes from the test against the 2-fold threshold
    padj   = res_thr[gene, "padj"]
  ) %>%
  arrange(padj) %>%
  filter(!is.na(padj))

# No fold-change filter here: the 2-fold requirement is already inside the test.
res_sig <- res_df %>%
  filter(padj < 0.05)

cat("Total genes tested        :", nrow(res_df), "\n")
## Total genes tested        : 16238
Code 
cat("Significant genes         :", nrow(res_sig), "\n")
## Significant genes         : 238
Code 
cat("  Upregulated             :", sum(res_sig$log2FoldChange > 0), "\n")
##   Upregulated             : 145
Code 
cat("  Downregulated           :", sum(res_sig$log2FoldChange < 0), "\n")
##   Downregulated           : 93

What testing against the threshold does. Testing against zero called ~4,150 genes at padj < 0.05. Requiring the change to be significantly larger than 2-fold leaves 238 genes (145 up, 93 down).

It is worth seeing how much of a difference the hypothesis makes. Filtering the old way — padj from the test against zero, then |log2FC| >= 1 on the shrunken estimates — gave 784 genes. Of those, 547 do not survive the proper test. They are not errors: their fold changes really do look larger than 2-fold. There is simply not enough evidence to say they exceed 2-fold rather than sitting just above it by chance. Only one gene is gained.

So the shorter list is not a stricter cutoff applied to the same question. It is the answer to the question we were claiming to ask all along.

Biological sanity check — known dexamethasone-responsive genes

Himes et al. highlighted several well-established glucocorticoid-responsive genes. We check where they land in our results rather than assuming — if the pipeline is working, these should be significant and in the expected direction (dexamethasone typically induces these).

Code 
known_genes <- c("DUSP1", "KLF15", "PER1", "TSC22D3", "CRISPLD2", "FKBP5", "ZBTB16")

res_df %>%
  filter(gene %in% known_genes) %>%
  select(gene, log2FoldChange, padj) %>%
  mutate(across(where(is.numeric), \(x) signif(x, 3))) %>%
  arrange(padj) %>%
  kable(caption = "Known glucocorticoid-responsive genes in our results") %>%
  kable_styling(bootstrap_options = c("striped", "hover"), full_width = FALSE)

How to read this. If these canonical genes appear with positive log2FC and small padj, it is strong evidence the analysis is capturing real glucocorticoid biology, not noise. A gene missing from the table was filtered out earlier for low counts (not expressed in these cells); that is not a problem in itself. In this dataset all of the recovered markers are strongly induced (positive log2FC) and highly significant — including FKBP5, TSC22D3 (GILZ) and ZBTB16, three of the most reliable glucocorticoid-response genes, and CRISPLD2, the gene the original study is named after. This is the expected positive-control result and confirms the pipeline is working correctly.

📘 Note: Known dexamethasone-responsive genes reported by Himes et al. include DUSP1, KLF15, PER1, TSC22D3 and CRISPLD2. Checking whether these appear among your top hits is a good biological sanity check — but let the analysis produce them rather than assuming their rank.
